# Architecture

## Shape

```
            ┌──────────────┐   ┌──────────────┐
 browser -> │ web (3000)   │   │ portal(3001) │  <- Next.js apps
            └──────┬───────┘   └──────┬───────┘
                   │  REST/JSON (OpenAPI) │
                   ▼                      ▼
            ┌────────────────────────────────────┐
            │  api (FastAPI, port 8000)          │
            │  routers -> services -> repository │
            └───────┬─────────────┬──────────────┘
                    │             │
             ┌──────▼─────┐  ┌────▼─────┐  ┌────────────┐
             │ PostgreSQL │  │  Redis   │  │  worker    │
             │ (Supabase  │  │ queue +  │  │ email poll │
             │  or local) │  │ cache    │  │ + SLA jobs │
             └────────────┘  └──────────┘  └────────────┘
```

## Layers
- `routers/` - HTTP surface only: validation, auth dependency, response shape. No business logic.
- `services/` - business rules: numbering, priority matrix (ITIL urgency x impact), SLA clocks against business calendars, notification audience resolution, AI orchestration.
- `repo/` + `db.py` - all SQL lives here. Parameterised statements only. No string interpolation of user input.
- `db/migrations` - append-only SQL. Never edited after release.
- `audit` - every state change writes actor, field, before/after, channel.

## Database
Postgres-first. Schema uses `bigint generated by default as identity`, `jsonb` for extension points and `text` + CHECK constraints instead of native enums, so porting to MySQL/MSSQL later is a mechanical mapping rather than a rewrite.

Local development uses container port **5433** because a native PostgreSQL 16 service already owns 5432 on the build machine.

## Tenancy
Single database, `tenant_id` on every business table, enforced in the repository layer. Domain separation (hierarchical org isolation) is planned for v1.5; the column layout already supports it.

## Prototype-depth markers
Code and docs mark stubs with `# prototype depth:` so nobody mistakes a stub for a finished feature. The README and `docs/SCOPE.md` list them.
